# 신뢰도 평가 (정답지 채점)

앱(추출 + 근거 검증)이 학교 공지에서 정보를 얼마나 맞히는지 잰다.
**AI를 학습시키지 않는다.** 사람이 만든 정답지와 앱 결과를 비교해 점수만 계산한다.

## 순서

1. **공지 모으기**: 학교 홈페이지 공지 본문을 `notices/공지ID.txt`로 저장한다. 캡처가 있으면 `공지ID.png`도 같이 둔다.
2. **정답 적기**: `answer_key.xlsx`의 `공지목록`, `정답지` 시트를 채운다. 방법은 `사용법` 시트에 있다.
3. **형식 점검**: `python -m eval.evaluate --check`
4. **채점**: `python -m eval.evaluate`
5. **결과 보기**: `results/<날짜_시각>/summary.txt`(지표), `items.csv`(항목별 채점 내역)

명령어는 모두 `backend` 폴더에서 `.venv`를 켠 상태로 실행한다.

## 채점 규칙

- 채점 항목은 6가지: 신청 대상, 신청 시작, 마감일, 결과 발표, 제출 서류, 제출 방법
- 날짜는 날짜가 같아야 정답. 정답에 시각을 적었으면 시각까지 같아야 정답
- 글자 항목은 띄어쓰기·기호 차이, 85% 이상 비슷한 표현, 한쪽이 다른 쪽을 포함하는 경우를 정답으로 본다
- 정답과 짝이 안 맞은 앱 항목은 **오답**(틀린 값이거나 지어낸 항목), 앱이 못 찾은 정답은 **누락**
- AI 답이 매번 다를 수 있어서 공지마다 기본 3번 돌리고, 모든 회차를 합쳐 계산한다

## 지표

| 지표 | 계산 | 의미 |
| --- | --- | --- |
| 추출 정확도 | 정답 앱 항목 / 앱 항목 | AI가 낸 정보가 맞는 비율 |
| 재현율 | 찾아낸 정답 / 정답 | AI가 빠뜨리지 않은 비율 |
| 확인됨 정밀도 | '확인됨' 중 정답 / '확인됨' | '확인됨'을 믿어도 되는지 |
| 오류 탐지율 | 틀린 항목 중 '확인 필요·근거 없음' / 틀린 항목 | 근거 검증이 실수를 잡는지 |
| 검증 전후 오류 | 틀린 항목 수 → 그중 '확인됨'으로 남은 수 | 사용자가 믿게 되는 틀린 정보가 얼마나 줄었는지 |
| 신뢰도 보정 | 점수 구간별 실제 정답률 | 90%라고 하면 실제로 약 90% 맞는지 |
| 일관성 | 모든 회차 결과가 같은 공지 / 공지 | 같은 공지에 같은 답을 내는지 |

## 옵션

```
--runs 3              같은 공지를 몇 번 돌릴지
--types txt,png       채점할 입력 형식 (형식별로 따로 점수가 나온다)
--only 공지01,공지02   일부 공지만
--sleep 2             Gemini 호출 사이 쉬는 초 (사용량 제한 대비)
--provider mock       API 키 없이 흐름 연습
```

공지 30건 × 3회면 Gemini를 약 90번 부른다. 무료 한도를 넘지 않도록 `--only`로 나눠 돌려도 된다.

## 다시 채점하기 (Gemini 안 부름)

채점할 때마다 앱의 답을 `results/<날짜_시각>/raw/`에 저장한다.
정답지나 채점 기준을 고친 뒤에는 Gemini를 다시 부르지 않고 저장된 앱 답으로 다시 채점할 수 있다.

```
python -m eval.evaluate --regrade 20261013_161048
```

앱(프롬프트·검증 규칙)을 고쳤을 때는 앱의 답이 달라지므로 `--regrade`가 아니라 새로 채점해야 한다.

## 같은 뜻으로 보는 경우 (글자 항목)

- 띄어쓰기·기호·`[서식2]` 같은 머리표 차이
- 같은 이메일 주소나 같은 사이트 주소가 양쪽에 있음, 같은 사이트 이름(영문)이 양쪽 글자에 있음
- 제출 방법에서 "이메일" ↔ 이메일 주소 (단, "온라인·홈페이지" ↔ 아무 사이트 주소는 같은 뜻으로 보지 않음)
- 짧은 쪽 내용의 70% 이상이 긴 쪽에 들어 있음
- 단, 숫자(평점 3.5, 12학점)가 다르면 항상 다른 답
- 앱이 정답 여러 개를 한 항목에 묶어 쓰거나, 정답 하나를 여러 항목으로 나눠 쓴 경우도 정답 (items.csv 비고 열에 표시)

## 허용 답

정답지 시트에 **"허용"** 열(메모 오른쪽)을 만들고 `O`를 적으면 그 줄은 허용 답이 된다.

| | 앱이 뽑으면 | 앱이 안 뽑으면 |
| --- | --- | --- |
| 필수 정답 (허용 칸 비움) | 정답 | 누락 (재현율 감점) |
| 허용 답 (허용 칸 O) | 정답 | 감점 없음 |

괄호·※ 설명, 제외 대상, 선택 서류처럼 "뽑아도 맞고 안 뽑아도 괜찮은" 정보에 쓴다.
허용 답은 정확도에만 반영되고 재현율 계산에는 들어가지 않는다.

## 묶음 (다 뽑거나 다 안 뽑거나)

정답지 **"묶음"** 열(허용 오른쪽)에 같은 이름을 적은 허용 답들은 한 묶음이 된다.

- 앱이 묶음을 **모두** 뽑음 → 정답 (감점 없음)
- 앱이 묶음을 **하나도** 안 뽑음 → 감점 없음
- 앱이 묶음을 **일부만** 뽑음 → 빠진 것을 누락으로 감점 (일부만 보여주면 오해를 만들기 때문)

예: "공인영어성적"은 필수 정답, TOEIC·TOEFL·OPIc·TOEIC Speaking 네 줄은 허용 O + 묶음 "공인영어성적".
묶음은 허용 답에만 쓴다.

## 근거 검증만 다시 (--reverify)

검증 코드(`app/agents/verification.py`)를 고쳤을 때는 AI 답은 그대로 두고 검증만 다시 돌린다.

```
python -m eval.evaluate --regrade 20261021_194556 --reverify
```

저장된 AI 답(값·근거 문장·AI 확신도)으로 지금 검증 코드를 다시 실행하므로 Gemini를 부르지 않는다.
AI 답이 완전히 같아서 점수 변화는 검증 코드의 효과만 보여준다. txt 공지만 지원한다.
