# 슬림형 하단 바

승인한 시안에서 홈 아이콘 위의 파란 표시를 뺀 형태로 구현한다.

- 구성은 `홈 / + 문서 추가 / 내 문서`다. 기존 Ionicons와 테마 색상·간격을 사용한다.
- 홈과 내 문서를 `MainTabs`의 두 탭으로 유지하고 공통 하단 바를 한 번만 표시한다. 흰색 바탕과 얇은 구분선, 선택된 화면의 파란 아이콘·글자로 구분한다. 가운데 +에는 원형 배경이나 위로 튀어나오는 장식을 넣지 않는다.
- 가운데 +는 기존 `DocumentAdd` 화면으로 이동한다. 홈의 기존 큰 문서 추가 버튼은 하단 바의 +로 대체한다.
- 내 문서는 로그인한 계정의 기존 문서 API 응답 전체를 보여준다. 마감이 지났거나 마감일이 없는 문서도 포함하며, 목업 데이터를 추가하지 않는다. 기존 API의 최신 등록순을 사용한다.
- 홈과 내 문서는 같은 화면 컴포넌트의 문서 카드·수정·삭제·열기 처리를 재사용한다. 등록한 문서는 관리 화면으로, 등록 전 문서는 기존 분석 결과 화면으로 이동한다. 화면에 돌아오면 기존 포커스 처리로 DB 내용을 다시 조회한다.
- 기존 홈 본문·상단 달력·알림·계정 메뉴와 문서 추가·분석·일정 관리 흐름을 유지한다. 시안의 예시용 ‘오늘의 준비’ 카드는 기능으로 추가하지 않는다.
- 하단 바는 스크롤 밖의 별도 영역을 차지하므로 마지막 카드와 겹치지 않는다. 기기의 하단 안전 영역을 적용하며, 시스템 홈 표시를 직접 그리지 않는다.
- 문서 추가 및 분석·편집 등 세부 화면은 루트 스택에서 열며, 뒤로 가면 출발한 탭으로 돌아온다. 기존 `resetToHome`·`backOrHome`도 `Tabs → Home` 경로를 그대로 사용한다.
- develop에서 추가된 전체 할 일·설정 화면은 상단 세 줄 메뉴에서 열 수 있다. 화면 기능을 유지하며 뒤로가기와 기기 하단 안전 영역을 적용한다. 달력은 기존 상단 아이콘으로 연다.

## 변경 파일

- `src/components/BottomNavigation.js`: 공통 하단 바, 선택 상태, 접근성 이름과 버튼 이동 연결.
- `src/screens/HomeScreen.js`: 기존 큰 추가 버튼 대체, 내 문서 표시 모드, 스크롤 여백 조정. 날짜 미정인 문서는 중립 색상 배지를 사용한다.
- `src/navigation/MainTabs.js`: 홈·내 문서 탭과 슬림형 공통 하단 바, 가운데 추가 버튼의 루트 스택 이동.
- `src/navigation/AppNavigator.js`: 탭 루트와 달력·전체 할 일·설정·세부 화면 경로 등록.
- `src/components/AccountSidebar.js`: 전체 할 일·설정 진입 메뉴. 기존 Google 연결·로그아웃·탈퇴를 유지한다.
- `src/screens/TodosScreen.js`, `src/screens/SettingsScreen.js`: 루트 스택 화면의 뒤로가기와 하단 안전 영역.
- `docs/bottom-navigation.md`: 동작·변경 범위 정리.

기능 브랜치는 `feature/slim-bottom-navigation`이다. 게스트 → Google 연결과 하단 바는 사용자 요청으로 커밋·push했다. PR #16의 대상은 `develop`이며, develop에 먼저 추가된 `@react-navigation/bottom-tabs`와 기존 루트 스택 구조를 재사용해 충돌을 통합한다. 별도 신규 라이브러리는 추가하지 않는다.

## 사용자 확인 순서

1. 로그인 후 홈 하단에 세 버튼이 보이고, 홈 아이콘 위에 파란 바가 없는지 확인한다.
2. 가운데 +를 눌러 기존 문서 추가 화면으로 이동하고 뒤로 돌아온다.
3. 내 문서에서 본인의 전체 문서가 보이며, 선택 색상이 내 문서로 바뀌는지 확인한다. 날짜 미정·마감 지난 문서도 표시되어야 한다.
4. 문서 열기·프로젝트 수정·삭제의 기존 기능을 확인한 뒤 홈으로 돌아온다.
5. 작은 화면과 하단 안전 영역이 있는 기기에서 마지막 카드가 하단 바에 가려지지 않는지 확인한다.
6. 상단 달력과 세 줄 메뉴의 할 일·설정을 열고 뒤로 돌아온다. 관리 화면의 홈 이동 후 슬림형 하단 바가 한 번만 보이는지도 확인한다.

실제 계정·DB 데이터를 사용하는 기능 테스트는 사용자가 진행한다. 이 프로젝트는 JavaScript로 작성되어 별도 TypeScript 검사 설정은 없다.

2026-10-26 확인 결과: 수정·추가한 JavaScript/JSX 3개 파일의 문법, 사용하는 Ionicons 이름, diff 공백 검사를 통과했다. Expo 웹 JavaScript 번들 생성과 웹·백엔드 상태 요청은 모두 200으로 응답했다. 계정 생성·로그인 조작·문서 등록·수정·삭제 테스트는 실행하지 않았다.

동일 날짜 PR 충돌 통합 후에는 `src`의 JavaScript/JSX 51개 파일 문법과 의존성 연결을 확인하고, 웹·iOS·Android용 Metro 번들이 모두 200 응답으로 생성되는 것을 확인했다. develop의 관리 화면 홈 이동과 공통 이동 헬퍼, 할 일 분류 로직·기존 테스트 파일은 그대로 보존했다. 실제 계정이나 모바일 기기를 이용한 기능 테스트는 실행하지 않았다.
